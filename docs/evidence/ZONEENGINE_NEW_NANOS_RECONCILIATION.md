## Wire and ordering

Ordinary cast announcement is the existing CastNanoSpell body: identity/caster are the casting player, target is the incoming target identity, Unknown=0 and Unknown1=0. This is not the NPC/triggered-cast contract. After durable success the ordinary sequence is FinishNanoCasting (Parameter1=1, Parameter2=nano ID), dirty stat projection, and SetNanoDuration when an actual active row exists. Replacing a different nano in the same strain additionally removes the old Buff. Removal uses the accepted Buff Action=0, NanoProgram identity; it does not invent a failed-cast or resistance packet.

Specializations are preflighted before generic cost commitment. Their Applied callback executes once after the durable transition on the owner tick. Keeper's accepted no-default-duration branch is represented explicitly, not inferred from generic NCU behavior.

Morph presentation does not overwrite original persisted character/equipment base values. Rebase drops the old owned overlay bookkeeping only after the caller clears bonuses, then recomputes the overlay against the current equipment result. Actual removal exposes the original base/current equipment contribution and emits the accepted monsterdata/isvehicle/mesh stat clears plus appearance/full update. Conflicting durable visual authorities are refused, not arbitrarily selected. Legacy rows with an already-morphed base cannot establish the original appearance from existing nano columns; hydration preserves and refuses that ambiguity instead of guessing an unmorphed base or erasing equipment. This compatibility limitation remains a release blocker for those affected rows.

The actual hoverboard graph includes `FlyingAllowed(112)`, whose accepted Legacy requirement evaluator explicitly returns true; this operator does not grant flight itself. New movement now requires server-owned IsVehicle=1 and current non-SL playfield authority before entering its existing Fly state, and returns to the prior walk/run mode when authority is removed. Checks occur after complete owner operations/on tick so a transient equipment rebase does not demote valid flight. Legacy move cases29/39 are no-ops, so this is a stronger state-authority repair, not proof of complete flight physics or client-coordinate validation.

Direct XP refill review found two concrete persistence divergences: wear effects were evaluated before the prospective level/title was installed, and the full refill was being saved into Health/CurrentNano Base without subtracting their owned Bonus. The progression adapter now prepares the new level/equipment/base maxima first, then uses `NanoService.ProjectBonusesAfterRebase` on detached stats to add actual active literals and recompute their derived resource bonuses before committing the refill. This helper does not modify the actor, process expiry, send packets or write the database. Detached-projection isolation, real active-bonus and conditional-equipment plan/publication equality tests PASS in the combined 307-test checkpoint. Legacy repeats final XP/IP in its per-level NewLevel packets and does not explicitly send Health on direct-reward level-up; those existing wire choices were retained.

The packaged Sparrow child273292 is **not** a marker-only nano: it declares duration1, NCU999 and OnTerminate RemoveNanoStrain functions for 251/841/252/818/247/766/224. The child is recorded in the ignored real-catalog audit, not silently skipped or replaced by a made-up no-NCU marker. Parent/cast/termination integration is still missing in this batch.
